# README and Project Documentation

## Workflow

1. Do not modify `README.md` unless explicitly requested by the user.
2. Inspect the repository, manifest (`composer.json`, `package.json`), SQL files (`database/`), scripts, and existing documentation.
3. Verify commands against the actual project instead of inventing setup steps.
4. Document prerequisites, installation, configuration, database setup, running, testing, and troubleshooting.
5. Explain required configuration parameters without exposing values or secrets.
6. Include MySQL/MariaDB import paths and migration notes when applicable.
7. Link detailed references instead of duplicating lengthy setup material.

## Documentation Sections

- Project purpose and audience
- Features
- Technology stack
- Prerequisites
- Installation
- Environment configuration
- Database setup
- Development server
- Tests and validation
- Build or deployment
- Folder structure
- API or usage notes
- Troubleshooting
